Next.js Implementation Guide: CapyQuiz Chill ZoneThis document outlines how to translate the index.html prototype into your existing Next.js architecture, which utilizes a Page -> ViewModel -> Repository -> DB pattern.The application is split into two main routes:Lobby: siswa/ujian/[jadwal_id]/quiz/lobby/page.tsxPlay: siswa/ujian/[jadwal_id]/quiz/play/page.tsxArchitecture OverviewFor each route, we will separate concerns:Page (View): React components responsible solely for UI rendering (Tailwind CSS, animations, state mapping).ViewModel (Controller/Store): Custom React hooks (e.g., useLobbyViewModel, useQuizViewModel) that handle business logic, local state management, and coordinate calls to the Repository.Repository (Data Access): Functions responsible for fetching and persisting data (API calls, DB queries).Database (DB): The underlying data structure (handled via Prisma, TypeORM, etc., depending on your stack).1. The Lobby ModuleRoute: app/siswa/ujian/[jadwal_id]/quiz/lobby/page.tsx (assuming Next.js App Router)A. Database & Repository (lobby.repository.ts)Purpose: Fetch necessary initial data for the lobby and handle quick quizzes.Functions needed:checkAvailability(jadwal_id): Verifies if the student can start the main quiz session.getRandomTrivia(jadwal_id): Fetches a single random trivia question for the quick quiz feature.B. ViewModel (useLobbyViewModel.ts)Purpose: Manage the state of the lobby and connect to the repository.State:mascotState: string ('idle', 'sleep', 'dance', 'eat').quickQuizState: object (question, options, isVisible, selectedAnswer, isCorrect).isLoading: boolean (for availability check).Actions:changeMascot(action): Updates mascotState and sets a timeout to revert to 'idle'.openQuickQuiz(): Calls Repository.getRandomTrivia, updates quickQuizState, and shows the modal.submitQuickAnswer(answer): Evaluates the answer, updates UI feedback state, and briefly changes the mascot based on success.handleCheckAvailability(): Calls Repository.checkAvailability. If successful, uses Next.js useRouter().push() to navigate to the Play route.C. Page Component (page.tsx)Purpose: Render the UI based on the ViewModel.Implementation Notes:Import the ViewModel: const { mascotState, quickQuizState, ...actions } = useLobbyViewModel(jadwal_id);Extract the UI elements from the HTML prototype (Header, Mascot Area, Action Buttons).Map the mascotState to actual image assets in your /public folder (e.g., /images/capy-${mascotState}.png).Implement the Quick Quiz as a standard React Modal or conditionally rendered overlay.2. The Quiz Play ModuleRoute: app/siswa/ujian/[jadwal_id]/quiz/play/page.tsxA. Database & Repository (quiz.repository.ts)Purpose: Fetch quiz batches and submit results.Functions needed:fetchQuestionBatch(jadwal_id, batchSize = 5): Retrieves 5 questions from the DB.submitBatchResults(jadwal_id, results): Saves the user's answers and score for the current batch to the database.B. ViewModel (useQuizViewModel.ts)Purpose: Manage the active quiz flow, scoring, and recap.State:questions: Array of question objects.currentIndex: number (0-4).score: number.userAnswers: Array of objects tracking { questionId, selectedOption, isCorrect }.quizPhase: 'loading' | 'playing' | 'recap' | 'error'.mascotMood: 'idle' | 'happy' | 'sad' (updates briefly during play, permanently on recap).Actions:loadBatch(): Calls Repository.fetchQuestionBatch and initializes state.submitAnswer(option):Checks if correct.Updates score and userAnswers.Briefly updates mascotMood for visual feedback.Waits (setTimeout ~1s) then increments currentIndex or changes quizPhase to 'recap' if it was the last question.finishBatch(): (Called internally when currentIndex > 4). Calls Repository.submitBatchResults. Calculates final mascotMood based on the score.startNextBatch(): Resets relevant state and calls loadBatch() again.returnToLobby(): Uses Next.js router to navigate back.C. Page Component (page.tsx)Purpose: Render the active question or the recap screen.Implementation Notes:Import the ViewModel: const vm = useQuizViewModel(jadwal_id);Conditional Rendering: Use vm.quizPhase to switch between a loading spinner, the main question layout, and the recap layout.Progress Bar: Calculate width dynamically: (vm.currentIndex / vm.questions.length) * 100.Animations: The CSS keyframes from the prototype (pulseCorrect, shakeWrong) can be added to your global CSS or Tailwind config. Manage the classes dynamically based on the user's selection state just before moving to the next question.Recap View: Map over vm.userAnswers to render the list showing the user's choice vs. the correct answer.General Translation Tips (HTML to React)Tailwind Configuration: Ensure the custom colors (capyBrown, capyGreen, etc.) and font settings defined in the HTML prototype's <script> tag are moved to your tailwind.config.js or tailwind.config.ts.Global Styles: The custom CSS rules (like .carpet, .bounce-anim) should be moved to your Next.js global stylesheet (e.g., globals.css or app.css).Class Names: Convert HTML class="" to React className="".Images: Replace the placehold.co URLs with standard Next.js <Image src="/path/to/local/file.png" /> components for better performance and asset management.State Management: Instead of manual DOM manipulation (document.getElementById(...)), rely entirely on React state updates from your ViewModels to drive UI changes.
